toolbox-export is a batteries-included CLI utility for [Fedora Toolbox](https://containertoolbx.org/) (Toolbx) users who want to launch containerized applications seamlessly from the host desktop or terminal — without manually crafting wrapper scripts or `.desktop` entries.

Run it once inside your container and toolbox-export handles everything: it detects the container name automatically, rewrites the app's `.desktop` launcher with the correct `toolbox run` invocation, copies icons to `~/.local/share/icons`, and drops a shell wrapper into `~/.local/toolbox` — all with a single command.

## What toolbox-export does

When you install an application inside a Toolbox container, it stays isolated from the host. toolbox-export bridges that gap by generating two host-side artifacts for each application:

- **Desktop launcher** — a patched `.desktop` file placed in `~/.local/share/applications` that launches the app via `toolbox run`
- **Binary wrapper** — a shell script placed in `~/.local/toolbox` that lets you invoke the CLI from any terminal on the host

<Steps>
  <Step title="Initialize">
    Run `toolbox-export init` once to create `~/.local/toolbox` and wire it into your shell's `$PATH`.
  </Step>
  <Step title="Enter your container">
    Use `toolbox enter <container>` to get a shell inside the container where your app is installed.
  </Step>
  <Step title="Export the application">
    Run `toolbox-export <appname>` to export the desktop launcher and binary wrapper in one shot.
  </Step>
  <Step title="Launch from the host">
    Close the container shell. The app now appears in your application menu and is callable from the host terminal.
  </Step>
</Steps>

## Key features

<CardGroup cols={2}>
  <Card title="Automatic container detection" icon="magnifying-glass">
    Reads `/run/.containerenv` to resolve the running container name — no manual configuration needed.
  </Card>
  <Card title="GUI & CLI support" icon="window">
    Exports both `.desktop` launchers for graphical apps and binary wrappers for command-line tools.
  </Card>
  <Card title="Icon extraction" icon="image">
    Copies PNG and SVG icons from `/usr/share/icons` and `/usr/share/pixmaps` to the host icon directory.
  </Card>
  <Card title="Interactive removal" icon="trash">
    Remove exported artifacts with `--rm`. A color-coded interactive prompt lets you selectively remove desktop files, icons, and binary wrappers.
  </Card>
  <Card title="Multi-shell PATH setup" icon="code">
    `toolbox-export init` patches `.bashrc`, `.zshrc`, `.profile`, and `fish/config.fish` automatically.
  </Card>
  <Card title="Multiple execution backends" icon="box">
    Wrapper scripts adapt to the calling context — `flatpak-spawn`, `toolbox run`, or `podman exec`.
  </Card>
</CardGroup>

<Note>
  toolbox-export must be **run from inside a Toolbox container**. It uses `/run/.containerenv` to detect and identify the container. Running it on the bare host will return an error.
</Note>
